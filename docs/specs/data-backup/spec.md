# 데이터 백업/복원

## 사용자에게 보이는 결과

상단 헤더(제목 옆)에 "내보내기"와 "불러오기" 버튼이 작게 생긴다. "내보내기"를 누르면 그 시점의 기록·실행 체크 상태·보유 종목이 담긴 파일이 내려받아진다. "불러오기"로 이전에 내보낸 파일을 고르면, 확인을 거쳐 지금 기록이 파일 내용으로 전부 바뀐다. 이 앱은 브라우저에만 데이터를 남기므로, 기기를 바꾸거나 브라우저 데이터가 지워져도 이 파일로 되돌릴 수 있다.

## 승인된 범위

- `finance-record`의 기록, `execution-guide`의 체크 상태, `holdings-tracking`의 보유 종목 세 가지를 한 파일에 담아 내보낸다.
- 불러오기는 항목 단위로 합치지 않는다. 지금 기록을 파일 내용으로 전체 교체한다.
- 교체 전에 확인 절차를 거친다. 취소하면 아무것도 바뀌지 않는다.
- 서버를 거치지 않는다. 파일은 사용자의 브라우저와 기기 사이에서만 오간다.
- 자동 백업, 클라우드 동기화, 여러 백업 파일의 이력 관리는 다루지 않는다.

## 수용 기준

1. "내보내기"를 누르면 그 시점 기록·실행 체크 상태·보유 종목이 담긴 파일이 다운로드된다.
2. 파일명에 내보낸 날짜가 들어간다.
3. 기록이 비어 있는 처음 쓰는 상태에서도 내보내기가 동작한다.
4. "불러오기"로 유효한 백업 파일을 고르면 교체를 확인하는 절차가 나온다.
5. 확인하면 지금 기록이 파일 내용으로 전부 바뀌고, 수입·지출부터 보유까지 모든 탭이 새 값을 보여준다.
6. 확인 절차에서 취소하면 지금 기록이 그대로 남는다.
7. 이 앱이 만든 백업 파일이 아니거나 손상된 파일을 고르면, 아무것도 바뀌지 않고 오류 안내가 나온다.
8. 내보내고 다시 불러온 파일은 내보내기 전과 같은 기록을 보여준다.

## 확정된 제약과 이유

- **항목 단위로 합치지 않고 전체 교체한다.** 같은 이름의 항목이 지금 기록과 파일 양쪽에 있을 때 어느 쪽이 더 최신인지 판단할 기준이 없다. 합치려다 오히려 기록을 헛갈리게 만들 위험이, 전체를 바꾼다는 사실을 명확히 알리는 것보다 크다.
- **서버를 거치지 않는다.** `PRODUCT.md`가 이미 "본인 한 사람이 자기 기기에서 쓰는 도구"로 경계를 그었다. 개인 재무 데이터가 담긴 백업을 서버로 보내면 이 경계와 부딪힌다.
- **상단 헤더에 작게 둔다.** 자주 쓰는 기능이 아니면서도 기록 전체를 바꿀 수 있는 만큼 항상 같은 자리에서 찾을 수 있어야 한다. 일곱 개 워크플로 탭과 나란히 두면 매일 쓰는 기능처럼 보여 오해를 준다.
- **불러오기 전에 확인 절차를 거친다.** 전체 교체는 되돌릴 수 없는 로컬 작업이다. 직전에 내보내 두지 않았다면 지금 기록은 사라진다.
- **잘못되거나 손상된 파일은 아무것도 바꾸지 않는다.** 일부만 적용되면 기록이 예전 값과 새 값이 섞인 채로 남아, 사용자가 지금 상태를 오해하게 된다.

## 가정

- 파일 형식은 JSON이고, 파일명은 `tanpotato-backup-YYYY-MM-DD.json` 형태다.
- 백업 파일은 finance-record, execution-guide, holdings-tracking 세 모듈이 지금 저장하고 있는 값을 그대로 담는다. 불러온 뒤에는 각 모듈이 이미 갖고 있는 버전 호환 로직(예: finance-record가 오래된 모양의 저장값을 읽을 때 빈 자리를 채우는 방식)을 그대로 탄다. 백업/복원 기능이 각 모듈의 데이터 모양을 새로 검증하지 않는다.
- 백업 파일 최상위에 이 백업 포맷 자체의 버전 번호를 둔다. 지금은 1이다. 세 모듈 중 하나가 저장 모양을 바꿔도 이 번호를 반드시 올릴 필요는 없다 — 각 모듈이 자기 버전 호환을 책임진다.

## 범위 밖과 이유

- **자동 백업, 정기 백업 알림** — 이번 범위는 사용자가 직접 눌렀을 때만 동작하는 수동 내보내기/불러오기까지다.
- **항목 단위 병합** — 위 확정된 제약에서 이미 뺐다.
- **여러 백업 파일의 이력 관리, 클라우드 저장** — 파일 자체의 보관은 사용자의 기기나 클라우드 저장소에 맡긴다.
- **백업 파일 암호화나 비밀번호 보호** — 남은 위험에 남기고 이번 범위에서는 다루지 않는다.

## 미룬 결정

- **항목 단위 병합이 필요한지** — 실제로 여러 기기를 오가며 쓰다가 전체 교체가 불편해지면 다시 정한다. 그때까지는 전체 교체가 잠정 동작이다.
- **백업 파일에 암호화를 걸지** — 개인 재무 데이터가 평문으로 담긴다는 위험을 인지했지만, 이번 범위는 암호화 없이 간다.

## 남은 위험

- 백업 파일은 암호화되지 않은 평문 JSON이라 개인 재무 정보가 그대로 담긴다. 파일을 아무 데나 두거나 공유하면 유출 위험이 있다.
- 전체 교체 방식이라, 백업해 두지 않고 다른 파일을 불러오면 그 시점까지의 기록이 되돌릴 수 없이 사라진다.
