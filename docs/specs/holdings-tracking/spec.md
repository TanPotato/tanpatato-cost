# 보유 종목 기록

## 사용자에게 보이는 결과

기존 여섯 탭에 일곱 번째 **보유** 탭이 생긴다. 티커(종목코드)를 입력해 종목을 추가하면 종목명과 그 시점 전일 종가가 자동으로 채워지고, 수량과 매수단가를 직접 적는다. 종목별로 매입금액·평가금액·평가손익·수익률을 보여주고, 전체 합계도 상단에 보여준다. "종가 새로고침" 버튼으로 등록된 모든 종목의 가격을 한 번에 갱신할 수 있고, 종목을 삭제할 수도 있다.

[execution-guide](../execution-guide/spec.md)의 여섯 단계를 모두 마쳤을 때 나오던 "다음 작업 단위에서 준비합니다" 문구는 이제 이 보유 탭으로 이어주는 버튼으로 바뀐다.

## 승인된 범위

- 종목은 [etf-candidate-selection](../etf-candidate-selection/spec.md)의 후보 3종목에 한정하지 않고, 티커만 알면 어떤 국내 상장 종목이든 추가할 수 있다.
- 종목을 추가할 때 종목명과 전일 종가를 함께 자동으로 조회해 채운다. 수량과 매수단가는 사용자가 직접 입력한다.
- "종가 새로고침" 버튼으로 등록된 모든 종목의 가격을 그 시점 값으로 다시 조회한다. 자동 갱신이나 실시간 시세는 없다.
- 종목별 매입금액, 평가금액, 평가손익, 수익률을 계산해 보여주고, 전체 합계도 별도로 보여준다.
- 종목을 삭제할 수 있다.
- 매매를 대신 실행하거나 증권사 계좌와 연동하지 않는다. 이 화면은 사용자가 이미 산 것을 스스로 기록하는 곳이다.

## 수용 기준

1. 유효한 6자리 종목코드를 입력해 추가하면 종목명과 그 시점 전일 종가가 자동으로 채워진 채로 목록에 나타난다.
2. 추가한 종목마다 수량과 매수단가를 입력할 수 있다.
3. 종목마다 매입금액(수량×매수단가), 평가금액(수량×전일 종가), 평가손익(평가금액-매입금액), 수익률(평가손익÷매입금액)이 표시된다.
4. 등록된 모든 종목의 매입금액 합, 평가금액 합, 평가손익 합, 전체 수익률이 화면 상단에 표시된다.
5. "종가 새로고침" 버튼을 누르면 등록된 모든 종목의 가격이 그 시점 전일 종가로 갱신된다.
6. 존재하지 않거나 조회에 실패하는 종목코드를 입력하면 목록에 추가되지 않고 오류 안내가 나온다.
7. 새로고침 중 일부 종목의 조회만 실패하면, 그 종목은 마지막으로 성공했던 가격을 그대로 유지하고 실패했다는 안내가 함께 나온다. 나머지 종목의 갱신은 정상적으로 반영된다.
8. 등록한 종목을 삭제할 수 있다.
9. 브라우저를 새로고침해도 등록한 종목·수량·매수단가·마지막으로 조회된 가격이 그대로 남아 있다.
10. [execution-guide](../execution-guide/spec.md)의 여섯 단계를 모두 체크하면 나오는 완료 카드가, 보유 탭으로 이동하는 버튼을 포함한 문구로 바뀐다.

## 확정된 제약과 이유

- **티커 제한을 두지 않는다.** 이 화면은 사용자가 실제로 산 것을 있는 그대로 기록하는 곳이다. `PRODUCT.md`의 "개별 종목은 추천하지 않는다"는 추천 엔진의 범위이지, 이미 산 것을 기록하는 이 기능의 범위가 아니다.
- **종목명은 직접 입력받지 않고 자동으로 조회한다.** 사용자가 이름을 타이핑하면 오탈자나 브랜드명 변경(과거 ARIRANG→PLUS ETF 사례로 이미 확인됨) 위험이 있다. 티커가 더 안정적인 식별자다.
- **가격 조회는 사용자가 "새로고침"을 눌렀을 때만 일어난다.** `PRODUCT.md`가 이미 "장중 실시간 시세는 제공하지 않는다"고 정했다. 자동 폴링은 이 경계를 흐리게 하고, 이 프로젝트가 쓰는 조회 방식([quote-source](../../decisions/quote-source.md))의 호출량도 늘린다.
- **일부 종목의 새로고침이 실패해도 나머지는 정상 갱신되고, 실패한 종목은 마지막 값을 유지한다.** 네트워크 문제로 한 종목 조회가 실패했다고 다른 종목까지 화면에서 사라지거나 0으로 보이면 사용자가 실제 보유 현황을 오해하게 된다.
- **매입금액이 0이면 수익률은 계산하지 않고 "-"로 표시한다.** 0으로 나누는 값은 의미가 없다.
- **전일 종가는 [quote-source](../../decisions/quote-source.md)가 정한 방식(네이버 증권 API, 서버 라우트 경유)으로 가져온다.** 인증키 발급이 필요한 공식 API 대신 고른 이유와 재검토 조건이 그 결정 계약에 있다.

## 가정

- 종목코드는 6자리 숫자로 형식을 검증한다. KRX 상장 종목의 표준 코드 형식이다.
- 수량은 1 이상의 정수로 입력받는다. 국내 상장 ETF·주식은 1주 단위로 거래된다.
- 데이터는 `features/holdings-tracking/` 전용 저장소에 별도로 둔다. 다른 기능의 기록과 섞지 않는다는 지금까지의 패턴(예: execution-guide의 체크 상태)을 그대로 따른다.
- 종목별로 평균 매수단가 하나만 기록한다. 여러 번에 걸쳐 다른 가격에 산 경우, 사용자가 평균을 계산해 입력한다고 가정한다.

## 범위 밖과 이유

- **증권사 API 연동이나 실제 매매 확인** — `PRODUCT.md`가 이미 범위 밖으로 정했다. 사용자가 스스로 확인해 기록한다.
- **실시간 시세, 자동 갱신** — `PRODUCT.md`의 "전일 종가 기준" 제약과 상충한다.
- **종목별 매수 이력(여러 매수 시점·수량·단가) 관리** — 이번 범위는 종목당 하나의 평균 매수단가까지다.
- **보유 비중과 추천 비중을 자동으로 비교하거나 재조정을 제안하는 기능** — `PRODUCT.md` 핵심 루프의 "비중 조정이 필요할 때 다시 돌아옵니다"에 해당하는 다음 작업 단위 후보다.

## 미룬 결정

- **보유 비중이 추천 비중과 얼마나 벌어졌을 때 재조정을 제안할지** — 이 기능이 아직 없어 지금은 다루지 않는다. 보유 종목 기록이 먼저 있어야 비교할 수 있다.
- **네이버 증권 API가 막히거나 응답 모양이 바뀌었을 때의 대체 조회 방법** — [quote-source](../../decisions/quote-source.md)의 "Reconsider when"에 재검토 조건으로 남겨 뒀다. 그때까지는 새로고침 실패로 나타난다.

## 남은 위험

- 네이버 증권 API는 공식 문서가 없는 비공개 엔드포인트라 예고 없이 막히거나 응답 모양이 바뀔 수 있다. 그렇게 되면 새로고침이 계속 실패하는 상태가 된다.
- 종목당 평균 매수단가 하나만 기록하므로, 실제로는 여러 번에 걸쳐 다른 가격에 산 경우 화면의 매입금액·수익률이 사용자가 직접 계산한 평균의 정확도에 좌우된다.
