# 전일 종가 조회 방식

## Decisions

- 보유 종목의 전일 종가는 네이버 증권 모바일 API(`m.stock.naver.com/api/stock/{티커}/basic`)를 호출해 가져온다. 공공데이터포털·KRX Open API처럼 인증키 발급이 필요한 공식 API는 쓰지 않는다.
- 이 API는 브라우저에서 직접 부르면 `Origin` 헤더 때문에 403이 떨어지므로, Next.js 서버 라우트를 하나 두어 그 라우트가 대신 호출하고 결과만 클라이언트에 돌려준다.
- 시세 갱신은 사용자가 "새로고침" 같은 동작을 직접 실행할 때만 일어난다. 자동 폴링이나 실시간 갱신은 하지 않는다.

## Boundaries

- 이 결정은 "이미 산 보유 종목의 가격을 어떻게 확인하는가"에만 적용된다. `etf-candidate-data`가 정한 "추천 후보를 무엇으로 채우는가"와는 다른 문제다.
- 네이버 증권 API는 공식 문서가 없는 비공개 엔드포인트다. 이 결정은 그 엔드포인트가 계속 지금과 같은 모양으로 동작한다는 것을 보장하지 않는다.

## Why

공공데이터포털과 KRX Open API는 모두 개인 인증키 발급 절차가 있고, 공공데이터포털 금융위원회 데이터는 실시간이 아니라 금요일 데이터가 차주 월요일에야 반영된다. 이 프로젝트는 본인 한 사람이 쓰는 개인 도구라 인증키 관리, 환경변수 설정, 발급 절차의 부담이 실익보다 크다.

네이버 증권 모바일 API는 인증 없이 종목코드만으로 종목명과 종가를 즉시 반환한다. 실제로 이 프로젝트가 추천하는 세 종목(102110, 360750, 273130)을 포함해 임의의 국내 상장 ETF 코드로 호출해 확인했다.

## Reconsider when

- 네이버 증권이 이 엔드포인트를 막거나 응답 모양을 바꿔 조회가 실패하기 시작할 때
- 인증키 없이 쓸 수 있는 신뢰할 만한 공식 API가 나올 때
- 여러 사용자가 쓰게 되어 네이버 서버에 대한 호출량이 문제가 될 만큼 늘어날 때

## Still-rejected alternatives

- 공공데이터포털 금융위원회 증권상품시세정보 — 인증키 발급이 필요하고, 데이터가 하루 이상 지연된다.
- KRX Open API — 인증키 발급이 필요하다.
- 사용자가 가격을 직접 입력 — 이번 작업 단위 논의에서 "네이버에서 가져오면 된다"로 명시적으로 결정을 바꿨다.

## Evidence worth preserving

- 2026년 9월 기준 `curl`로 직접 확인: `https://m.stock.naver.com/api/stock/{code}/basic`은 인증 없이 `stockName`, `closePrice`, `marketStatus`, `localTradedAt`을 반환한다. `Origin` 헤더를 붙이면 403이 떨어져, 브라우저 직접 호출이 아니라 서버 프록시가 필요함을 확인했다.
